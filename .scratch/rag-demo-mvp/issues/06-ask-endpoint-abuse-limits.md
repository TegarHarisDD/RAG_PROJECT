# 06: POST /ask streaming endpoint + abuse limits

**What to build:** The API the UI will consume: a Question arrives, the answer streams back as Server-Sent Events, and the stream ends with a Citations payload (Document, page, verbatim Chunk text). Abuse protection enforces per-IP hourly limits, Question length cap, and a global daily stop that keeps real traffic under the provider's free daily cap — the last two protect the recruiter-click experience. Provider and database failures come back as clean, mapped errors.

## Comments

- **SSE contract** (`app/main.py`): `POST /ask` accepts `{"text": ...}` and streams named SSE events the UI can parse directly — `token` `{"text"}` (one per streamed fragment), `refusal` `{"message"}` (the distinct Refusal outcome), `citations` `{"citations": [{source, page, chunk_index, text, score}]}` (the terminal payload, verbatim Chunk text via `asdict(Citation)`), and `error` `{"kind", "message"}` where kind ∈ `store` | `provider` | `generation` | `internal`. `Cache-Control: no-cache` + `X-Accel-Buffering: no` so Render's proxy doesn't buffer the stream.
- **Streaming without duplicating orchestration**: `app.rag` gained `ask_stream()` — an event generator (`TokenEvent` … `FinalEvent`) that the CLI-facing `ask()` is now implemented on top of, so the endpoint streams tokens as they arrive and all orchestration (retrieval, refusal short-circuit, prompt assembly, fallback chain via `on_attempt`) stays in one place. CLI behavior is unchanged (61 pre-existing tests pass untouched).
- **Abuse limits**: `app/abuse.py` `AbuseLimiter` — sliding 1-hour windows per IP + a UTC-daily global counter, one atomic `reserve(ip)` under a lock (check-and-count in a single step so concurrent requests can't race through a check-then-record gap), injected clock for deterministic tests. Daily stop is checked first so a first-time visitor during an exhausted day gets the honest "come back tomorrow" rather than a misleading per-IP message. Rejected asks consume no quota. Counters are in-memory (single free-tier worker; a restart errs generous). Stale IPs are pruned each reserve so the map stays bounded to the last hour's visitors. Limits are env-configured via new `AbuseConfig`/`load_abuse_config` in `app.config` (`QUESTION_MAX_CHARS=500`, `RATE_LIMIT_PER_HOUR=5`, `DAILY_QUESTION_LIMIT=40`, same clean-error conventions as the other loaders, documented in `.env.example`).
- **Rejections are explicit**: over-length and blank/whitespace-only Questions → 422 (Pydantic `Field(max_length)` + a `field_validator`); abuse limits → 429 JSON `{"error": "rate_limit" | "daily_limit", "message": ...}` naming which limit bit. The server IP comes from the last X-Forwarded-For entry (the one our own proxy added — earlier entries are client-spoofable), falling back to `request.client.host`.
- **Error mapping**: Atlas/store failures surface as `error` kind `store` — the store is built inside the stream via a `get_store_factory` dependency whose module-level `_make_store` is `lru_cache`d (failures aren't cached, so a failed cold start retries), never as a dependency-time 500. Embedding failures → kind `provider`; exhausted fallback chains → kind `generation`; anything unexpected → kind `internal` (a terminal event, not a silently dropped connection). All messages are the clean `ProviderError`/`IngestError` strings — no stack traces.
- **Test injection seam**: FastAPI `dependency_overrides` — tests retarget `get_store_factory`, `get_provider_config`, `get_retrieval_config`, `get_limiter`, `get_embed_fn`, `get_generate_fn`. Shared fakes (`FakeStore`, `hit`, `recording_embed`, `fake_generate`, test configs) live in `tests/conftest.py` so the rag and API seams can't drift apart.
- Code-review findings (6, all accepted): per-request store-factory caching bug (fresh `lru_cache` closure per request → connection churn); TOCTOU race in check-then-record (fixed with atomic `reserve`); unbounded per-IP map (fixed with staleness pruning); missing catch-all error event; whitespace-only Questions burning quota (fixed with blank validator); duplicated test fakes (moved to `conftest.py`).
- 85 tests passing, mypy clean. No live verification needed: every path here is behind the fake seams; the only real-network behavior is the provider/Atlas code already live-verified in tickets 02–05.
